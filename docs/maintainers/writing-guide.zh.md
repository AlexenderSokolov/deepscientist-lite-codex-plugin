# DeepScientist Lite 中文写作规范

这份规范用于 README、用户指南、课程、技能说明和发布文档。目标不是统一文风，而是让读者知道自己能做什么、会看到什么，以及哪些判断仍需人工完成。

## 先决定读者和任务

- README 面向第一次使用的人：先给可执行入口，再给机制和边界。
- 用户指南面向想弄懂插件的人：解释问题、机制、可观察结果和限制。
- 课程面向学生：给步骤、检查点、失败现象、提交物和答案。
- 实现与维护文档面向维护者：允许使用 schema、事务和迁移术语，但要给具体对象。

同一段不要同时承担安装教程、架构说明和发布审计三种任务。

## 术语第一次出现时要落地

- artifact：先写“阶段记录（artifact）”，说明它是给人读的文件。
- Evidence Pack：先写“证据包（Evidence Pack）”，列出契约、日志、指标和哈希。
- revision：写成“单调递增的状态版本号”，不要称为完整历史快照。
- review gate：写成“分析前的审查步骤”，不要暗示独立模型或自动真理判定。
- Graph：说明它保存公开节点和关系，不保存隐藏思维链。

## 每个机制回答四个问题

1. 它解决什么实际问题？
2. 它怎样工作？
3. 用户能看到什么文件、状态或错误？
4. 它不能保证什么？

如果一段只有概念和优点，没有可观察结果，应补例子或删掉。

## 能力声明分三级

- **已验证事实**：有当前代码、测试或审核记录支持，例如“陈旧 revision 返回退出码4”。
- **设计目的**：说明为什么这样做，例如“用于减少并发覆盖”；不要写成绝对保证。
- **未来方向**：明确尚未实现，不写进当前功能列表。

避免“深刻、极致、严苛、完美、彻底、绝对保证、杜绝幻觉”等词。确需表达强约束时，直接写触发条件、行为和退出码。

## 示例要能复制，也要说明前提

- 命令必须标明从仓库根目录还是项目目录运行。
- 提示词写清允许和禁止动作。
- 示例输出不能伪装成真实技能调用结果。
- 教师答案必须标记为参考，不能提前进入 student 工作区。
- 路径、密钥和外部数据示例使用占位值，不提交本机根目录。

## 版本事实维护

版本号、技能数量、测试数量和平台结果容易过期。当前状态写入 release status 或版本审核；历史审核保留当时数字，不回写成当前数字。用户文档尽量描述验证入口，不硬编码测试总数。

引用 Codex 能力时只使用 OpenAI 官方资料；引用 DeepScientist 上游时优先官方仓库和文档。二手建议可以启发课程，但不能直接变成产品事实。
