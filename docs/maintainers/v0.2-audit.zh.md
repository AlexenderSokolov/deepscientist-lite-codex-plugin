## 本轮结构分析与必要改进

### 已采取

- 增加 `.gitattributes`，对 shell、Python、Markdown、JSON 和 YAML 强制 LF，对 PowerShell 使用 CRLF，降低 Windows checkout 后的 WSL 解析风险。
- `run_validate.sh` 支持 `PYTHON_BIN`，否则依次发现 `python3` 和 `python`；这修复了 Ubuntu 默认只有 `python3` 的兼容风险。
- PowerShell 包装同步支持 `PYTHON_BIN`，两端均设置 `PYTHONDONTWRITEBYTECODE=1` 与 `PYTHONUTF8=1`。
- 状态 CLI 对 stdout/stderr 的不可编码字符使用反斜杠转义；测试和验证器显式按 UTF-8 解码子进程输出。这样既保留 graph 文件中的原始 Unicode，也不要求调用者恰好使用中文 Windows 代码页。
- 修正设计文档中“summary/reason 没有 UTF-8 文件入口”的过时陈述。

### 本轮不拆分状态脚本

`ds_lite_state.py` 当前约 1310 行，将锁、路径、schema、迁移、渲染、CLI 和命令实现集中在一个标准库脚本中。单文件便于插件分发和教学检查，但已经增加维护与局部修改风险。本轮 Windows/WSL 测试没有发现需要靠模块拆分才能修复的问题，因此临近发布时不做大范围重构；测试覆盖用于控制当前风险，模块化进入后续 P1。

## 自我反思

1. **CI 配置不是 CI 证据。** 此前可以确认 workflow 已写入，却不能在未推送时声称 Windows/Ubuntu 远程矩阵已通过。审核报告将本地证据与远程证据分开记录。
2. **CLI 测试不能替代真实技能使用。** 当前测试能证明状态内核、模板和命令协议，但不能证明新用户一定能安装插件、正确触发五个 skills，或在长会话中始终维护 PROJECT/STATUS/artifact 一致性。
3. **graph 与地图不是单一事务。** Graph JSON 可以锁定并原子替换，Markdown 投影仍可能在进程中断时落后；revision/stale 检测提供的是可发现、可修复保证，不是跨文件原子提交。
4. **保留旧实现有成本。** 为遵守“不删除文件”，v1 脚本作为 legacy 审计文件保留，这提高了包体和读者辨识成本；文档必须持续强调唯一运行入口是 `ds_lite_state.py`。
5. **法律与品牌说明不是法律审查。** LICENSE、NOTICE 和非官方声明降低混淆风险，但不能替代正式法律意见。
6. **“Windows 通过”仍可能掩盖区域设置差异。** 中文 Windows 的默认代码页可以输出中文，GitHub 英文 Windows 的西文 `charmap` 不行。以后跨平台验收必须同时覆盖文件编码和终端/管道编码，不能把操作系统名称当作充分环境描述。
